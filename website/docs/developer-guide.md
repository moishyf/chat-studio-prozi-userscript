# פיתוח והפצה

נדרש Node.js 22 ומעלה. אין התקנת חבילות.

```sh
npm run build
npm test
npm run serve
```

פתחו http://127.0.0.1:4173/tests/fixture.html. הכפתורים מריצים את המנוע האמיתי מול נתוני דמה. סביבת fixture כוללת GM מדומה ב־localStorage; אין לכלול אותה בקובץ ההפצה. שרת הבדיקה מאזין רק ל־127.0.0.1.

להשוואת כל 99 נכסי SVG: הריצו `node scripts/build-asset-test.mjs` ופתחו `http://127.0.0.1:4173/.local/asset-test.html`. מוצגים קובץ המקור וה־DOM שמיוצר על ידי מנוע הנכסים של המוצר, זה לצד זה. קובצי בדיקה זמניים נוצרים רק ב־.local ואינם מועלים למאגר.

ערכו יחידה ב־src/core או מתאם ב־src/runtime. סדר החיבור מופיע ב־src/order.json. אין לערוך dist ידנית. אין להריץ שוב את convert.mjs על פרויקט שכבר הומר. אין לשנות original/v15.3.

בכל שינוי: הריצו Build ובדיקות, בדקו דפדפן בתרחיש הרלוונטי, ועדכנו CHANGELOG ו־TEST_REPORT. לפני שחרור יציב השלימו את בדיקות Google/Tampermonkey המסומנות כממתינות. שינויי Google מחייבים בדיקת selectors, לא החלפת המנוע כולו.

עדכון גרסה מתבצע ב־package.json. אל תשנו @name או @namespace. קובצי המטא וההתקנה נוצרים יחד ומופצים מאותו commit. תהליך CI בונה מחדש, מריץ בדיקות ומשווה את התוצר לתוצר שהועלה. workflow של release דורש אישור מפורש כי בדיקות הדפדפן הושלמו; אינו מכריז שבוצעו על סמך Build.

חזרה לאחור: שחזרו קוד של תג מוכר, העלו מספר גרסה חדש ובנו שוב. אין להפחית את @version ולצפות ש־Tampermonkey יעדכן אוטומטית. לפני שינוי schema גבו מידע והוסיפו בדיקת מיגרציה.

המאגר נוצר בנפרד מהמקור. אפשר להמשיך עם Codex: ציינו את התכונה, תרחיש השחזור וקובץ TEST_REPORT, ובקשו שינוי ממוקד תוך שמירת בדיקות הקטלוג.
